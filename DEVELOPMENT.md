# Работа над игрой без пересылки вложений

## Текущее состояние

Рабочая ветка подготовки: `test/css-roundtrip`. Публикация сайта этим workflow не выполняется. Файлы опубликованной игры в корне не заменять автоматически.

## Где править

- `src/template.html`: разметка и порядок подключения блоков.
- `src/styles.css`, `src/styles-N.css`: стили по номеру маркера CSS_BLOCK_N.
- `src/scripts/script-NN.txt`: содержимое script-блоков по номеру SCRIPT_SOURCE_NN. Расширение txt не означает, что файл не содержит JavaScript. Некоторые блоки содержат JSON: прежде чем править, сверить тип script в шаблоне.
- `src/html-assets/` и `src/css-assets/`: base64-ресурсы. Имена соответствуют SHA256 самих байтов b64-файла; при замене ресурса нужны новое имя и обновление маркера. Одобренного льва без согласования не менять.

## Сборка

Из корня репозитория: `python3 scripts/build_game.py`. Результат: `preview/index.html`. Сборка не публикует игру и не меняет корневой index.html.

Для локального просмотра: `python3 -m http.server 8765 --directory preview`, затем открыть localhost:8765. Это отдельный origin: сохранение рабочего сайта автоматически здесь не появится.

## Две независимые проверки

1. Frozen baseline round-trip: собирает исходники зафиксированного коммита `03d3f537e326718b1fdd769c8679a1fe66d03e55` и сравнивает с его game-1.txt + game-2.txt байт в байт. Это проверка точности переноса исходной версии, не требование к новым игровым изменениям. Для проверки используется текущая версия сборщика.
2. Current sources browser test: собирает текущие исходники без сравнения со старой игрой, открывает их в чистом Chromium 844x390, ждёт экран создания или выбора героя и проверяет необработанные ошибки JavaScript при старте.

Зелёный тест не доказывает корректность боёв, инвентаря, наград или миграции сохранений. Такие проверки нужно добавлять отдельно.

В Actions сохраняются browser-smoke-results (скриншот и ошибки при достижении браузерного шага) и game-preview (сборка после успешного браузерного теста). Артефакты хранятся 14 дней. Их не требуется пересылать в чат для каждой правки.

## Порядок изменений и публикации

1. Читать актуальные файлы из GitHub, а не восстанавливать код по памяти чата.
2. Делать небольшие правки в исходниках тестовой ветки.
3. Проверять сборку и браузерный тест; отдельно тестировать затронутую игровую механику.
4. Перед публикацией согласовать точный состав изменений и способ переноса на рабочий сайт; резервную копию сохранения держать отдельно.
5. Публикация пока не автоматизирована. Не сливать тестовую ветку и не заменять index.html, game-1.txt, game-2.txt без отдельного согласования.

Ассистент не следит за Actions или прохождением в фоне. Если журнал Actions недоступен через подключённые инструменты, достаточно скопировать текст ошибки в чат. Новые внешние записи требуют подтверждения.
